# API client (`src/lib/api-client`)

Built on `openapi-fetch` over types generated by `openapi-typescript` from `openapi/openapi.json`.

## Base URL

`NEXT_PUBLIC_API_BASE_URL` includes the `/api/v1` prefix (e.g. `http://localhost:8000/api/v1`). The generated
paths **already start with `/api/v1`**, so the HTTP client is rooted at the origin (`apiRoot`, i.e. the base
with a trailing `/api/v1` removed) and `apiBaseUrl` is used for the few raw calls (dev token). The upload
session's relative `upload_url` (`/api/v1/uploads/<id>/content`) is resolved against `apiRoot`
(`resolveUploadUrl`).

```ts
const folder = await call<Folder>(
  api.GET('/api/v1/folders/{folder_id}', { params: { path: { folder_id } }, signal }),
);
```

`call()` unwraps `{ data }`; errors are thrown by the fetch layer, so TanStack Query sees them directly.

## Behaviour

| Concern         | Implementation                                                                                                                                                                                       |
| --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Headers         | `Authorization: Bearer <token>` from the AuthProvider, `X-Organization-Id` once known (every request)                                                                                                |
| Errors          | `ApiError { status, code, message, requestId, details, retryAfterSeconds, fieldErrors }` parsed from `{"error": {code,message,request_id,details}}`; falls back to FastAPI shapes and `x-request-id` |
| Friendly text   | `friendlyMessage(err)` maps codes (`name_conflict`, `stale_version`, `quota_exceeded`, `unknown_recipient`, ...)                                                                                     |
| Retries         | **Only** `GET`/`HEAD`, on network errors and 502/503/504, max 2 retries with backoff. Writes are never retried automatically                                                                         |
| 401             | Refresh the session once (`AuthProvider.refresh`) and replay (bodies are cloned); if still 401 or no refresh -> `onSessionExpired` (sign out, redirect `/login?reason=expired`). No refresh loops    |
| 429             | `Retry-After` parsed into `retryAfterSeconds`; a toast is shown by the session layer                                                                                                                 |
| Cancellation    | `AbortSignal` passes through (TanStack Query supplies it); aborted calls throw `ApiError(code="aborted")`                                                                                            |
| Idempotency     | Upload initiation sends a fresh `Idempotency-Key` (UUID) per attempt                                                                                                                                 |
| Pagination      | `limit` + `offset` -> `{items,total,limit,offset}`; `PaginationBar` + helpers in `pagination.ts`                                                                                                     |
| Upload progress | `putBytes` uses `XMLHttpRequest` (fetch has no upload progress); raw bytes, `application/octet-stream`                                                                                               |
| Integrity       | `sha256Hex` (WebCrypto) is sent with the initiate request; files > 100 MB are rejected client-side                                                                                                   |

## Contract workflow

```bash
npm run api:sync     # copies ../enterprise-dms-backend/docs/api/openapi.json (or $DMS_BACKEND_DIR) and regenerates types
npm run api:types    # regenerate from the pinned snapshot
npm run api:check    # CI: regenerate to a temp file and fail on drift
```

Never hand-write API shapes elsewhere; add aliases in `types.ts` instead.
